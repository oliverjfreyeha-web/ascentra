# Course import file (format versions 1 and 2)

> **Two formats.** Format version 1 (this first part) is for **businesses and side hustles**: a course of modules
> with a size tier and a capstone. Format version 2 ([below](#format-version-2-a-skill-track)) is for **skills**: a
> track of 3 Rounds of 5 sections. A version 1 file for a skill, or a version 2 file for a business or side hustle, is
> refused with a message saying which format to use.

Courses are written with the Owner in chat, not generated by the app. The Owner saves the finished course as one JSON
file and imports it at **Admin → Import course** (`/admin/import`, Owner only). The schema is defined once, in code:
`lib/courses/import-format.ts`. This page describes it for people.

**What happens:**

- **Check file** is a dry run. It writes nothing except an audit record.
- **Create Draft** runs the same check, then creates a new **Draft** course version in one database transaction:
  all or nothing.
- Nothing is published or approved. The course follows the usual flow:
  1. lesson review
  2. Reviewer verification
  3. the Owner's approval of each module
  4. publish
- A topic whose course was ever published is refused. A published version is never touched.
- An existing Draft is left as it is; the import becomes the next version.

**The file is data, not instructions.**

- Every string has HTML and scripts removed.
- Links must be `https://`.
- Nothing in the file is fetched or run.
- The income-claims check and the "attorney-approved" check run on every text field. A file with a claim is refused,
  with the exact words and their path.

## Limits

- One file, 2 MB at most, `formatVersion: 1` (or `2` for a skill track, below).
- Unknown fields are refused, so a typo can't be silently dropped.
- Problems are reported with their path in the file, for example `modules[2].items[4].sourceIds[0]: unknown source "s9"`.

## Top-level fields

| Field | What it is |
|---|---|
| `formatVersion` | `1` |
| `topicSlug` | An existing topic (business, side hustle or skill) from `/admin/topics`, not yet published as a course. |
| `course` | See the course fields below. |
| `sources[]` | `id` (your own short id, like `s1`), `kind` (`youtube`, `official`, `article`, `owner_tip`), `title`, `link` (https), `creditLine`, `licenseClass` (`open`, `owner_supplied`, `web_summarize_only`). No transcripts. |
| `resources[]` | `name`, `link`, `license`, `termsChecked`, `okToUseText`, `checkedOn`. A resource with `termsChecked: false` is stored but never shown to learners. |
| `freshnessWatch[]` | `what`, `link`, `howOften`. Stored for the next stage (C3), not acted on yet. |
| `capstone` | See the capstone fields below. |
| `modules[]` | See the module fields below. |

**Course fields (`course`):**

- **Required:**
  - `title`
  - `sizeTier` (`compact`, `standard`, `large`)
  - `hoursPerWeek` (`min`, `max`)
  - `roadmap`, `audience`
  - `teenStatus` (`status`: `open` or `hidden`, plus `reason`)
  - `outcomes[]`
  - `requirements` (`ageLimits`, `licenses`, `taxes`, `platformAccounts`, each optional)
- **Optional:**
  - `legalChecklist[]`
  - `notices` (`license`, `software`)
  - `marketing`, `growth[]`
  - `glossary[]` (`term`, `meaning`)
  - `toolsAndCosts[]` (`tool`, `what`, `cost`: `free` or `paid`, `priceRange`, `link`, `checkedOn`)
  - `commonMistakes[]`
  - `skillsTaught[]` (skill slugs)
  - `coverageChecklist[]`

**Capstone fields (`capstone`):**

- `title`, `brief`, `deliverables[]`, `selfCheck[]`.
- `automation` is required for a business course. It holds:
  - `whatAutomated`
  - `masterPrompts[]` (`title`, `purpose`)
  - `aiPlans[]` (`name`, `price`, `link`, `checkedOn`; at most 3; leave it empty and learners see "a paid plan may be needed")

### Modules

There must be as many modules as the size tier allows: Compact 3–4, Standard 5–6, Large 7–9.

Each module has:

| Field | What it is |
|---|---|
| `number` | 1, 2, 3… in order |
| `title` | |
| `difficulty` | 1–5, never lower than the module before |
| `bigQuestion`, `canDo[]`, `hours` | |
| `keyTerms[]`, `examples[]`, `mistakes[]` | |
| `sourceIds[]` | |
| `recipe` | `videos`, `quizzes`, `assignments`, `sandboxes`, `sequences` (each within the C1 caps), `boosters[]` (from the learning boosters list) |
| `lessons[]` | 1–6 |
| `items[]` | at least 3 different task types per module |

**Each lesson** has:

- `title`, `minutes`, `objectives[]`, `summary`
- `sections[]` (`heading`, `paragraphs[]` of `text` and `sourceIds[]`)
- `takeaways[]` (`text`, `sourceIds[]`)

Each lesson becomes a Draft lesson version with numbered citations.

**Each item** has:

- `kind`: `video`, `quiz`, `assignment`, `sandbox`, `sequence` or `booster`.
- `title`.
- `lesson`: which of the module's lessons it belongs to. Defaults to 1.
- `importance`: `should_know`, `important` or `very_important`. A Very important item also needs a `notebookNote` of
  20–800 characters.
- `sourceIds[]`: at least one, and every id must be in `sources`.
- **A video** has a `videoBrief`:
  - `mustCover[]`, `lengthMinutes`, `tone`, `onScreenExamples[]`, `sourceIds[]`, `avoid[]`
  - It becomes a video slot "Waiting for video".
- **Every other item** has:
  - `taskType`, one the app supports: `multiple_choice`, `true_false`, `matching`, `ordering`, `flashcard`,
    `short_answer`, `build_it`, `branching_scenario`, `spot_the_mistake`, `case_teardown`, `teach_back`, `mini_project`.
    It must fit the kind (a quiz is a code-graded type, and so on).
  - `prompt` and `explanation`.
  - `content` (and, for the five code-graded types, `answerKey`) in that type's existing shape:
    - multiple choice: `content.options[]`, `answerKey.correct`
    - ordering: `content.steps[]`, `answerKey.order[]`
    - short answer: `content.sampleAnswer`
    - spot the mistake: `content.passage`, `content.mistake`
  - A `booster` item also names its `booster`.
  - A sandbox is shown to learners as "Practice (simulated)".

## Where it goes

The importer creates exactly what the existing tables hold. It creates no parallel tables:

| In the file | Stored as |
|---|---|
| the course | a new `courses` row (Draft, `owner_review_required`, `size_tier`, the notices) |
| modules | `modules` (title, recipe) |
| lessons | `lessons` + `lesson_versions` (Draft, `generated_by` person, citations) |
| video items | `video_slots` (waiting for video, with the brief, importance label and Notebook note) |
| other items | `activity_items` (Draft, with type, part, booster, importance label, Notebook note, citation) |
| sources | the source library (`sources`): reused by link, or added as "proposed" for the usual approval |
| capstone | `course_capstones` |
| guide, resources, freshness watch, module details | the import record: an `academy_blueprints` row (kind course, made by a person, approved by the Owner) |

The topic is linked to the catalog the same way "Start course" links it. The topic's cost, outlook and teen settings are
never written: the Owner sets those in `/admin/topics`.

# Format version 2: a skill track

A skill is learned as one **track**: 3 Rounds of 5 sections. Rounds 2 and 3 go over the same 5 sections again, harder.
There is no size tier, module count, rank gate or capstone. How learners move through a track is in
[SKILL-TRACKS.md](SKILL-TRACKS.md). The schema is `ImportTrackFile` in `lib/courses/import-format.ts`.

**What is the same as version 1:** Check file and Create Draft; one transaction, all or nothing; the file is data, not
instructions (HTML and scripts removed, `https://` links only, nothing fetched or run); the income-claims and
"attorney-approved" checks on every text field; unknown fields refused; 2 MB at most; Owner only; every check and import
audited with the file's name, size, sha256 hash, the topic, the Round numbers and the counts (never the contents).

**What is different:**

- `formatVersion: 2`, and the topic must be a **skill**.
- A file holds **one Round or all three** (or Rounds 1 and 2). Round *r* can't be created before Round *r*−1 exists, in
  the same file or already stored as a Draft or Published version.
- An import always makes a **new Draft version**. It holds the file's Rounds plus a copy (as Drafts) of the stored Rounds
  the file doesn't replace. A published version is never touched, so a skill that is already published can still take a
  new Round: the new version goes through review and approval as usual, including the carried sections.

## Top-level fields (version 2)

| Field | What it holds |
|---|---|
| `formatVersion` | `2` |
| `topicSlug` | the slug of an existing **skill** in `/admin/topics` |
| `track` | `title`, `audience`, `outcomes` (1-12), `requirements` (`ageLimits`, `licenses`, `taxes`, `platformAccounts`, all optional), `glossary`, `commonMistakes`, `teenStatus` (`open` or `hidden`, with a reason; a warning only: the topic isn't changed), `skillsTaught` |
| `sources` | as in version 1 |
| `resources` | as in version 1 |
| `freshnessWatch` | as in version 1 (stored only) |
| `rounds` | 1 to 3 Rounds, each: `roundNumber` (1-3, each once), `label`, `goal`, and `sections` (exactly 5) |

## Sections

A section has **the same fields as a version 1 module** (`number` 1-5, `title`, `difficulty` 1-5, `bigQuestion`,
`canDo`, `hours`, `keyTerms`, `examples`, `mistakes`, `sourceIds`, `recipe`, `lessons`, `items`) and the same
checks: the recipe caps, at least 3 different task types, labels, Notebook notes for "Very important" items, sources.

**Difficulty:**

- Within a Round, difficulty never goes down from one section to the next.
- Section *k* of Round *r* is at least as hard as section *k* of Round *r*−1.
- Round *r*'s average difficulty is higher than Round *r*−1's.
- These are checked against the earlier Round when it is in the file or already stored.

**Items** take one more kind, `task`: a **hands-on task**. Its `taskType` is one of the existing hands-on types,
`build_it` (filling the simulated-practice part) or `mini_project` (filling the assignment part), with
`content.checklist` of 2 to 10 steps. New hands-on types are not part of this stage.

## Where it goes (version 2)

| In the file | Stored as |
|---|---|
| the track | a new `courses` row: Draft, `owner_review_required`, `is_track`, no size tier |
| each section | a `modules` row with its `round` (1-3); Round *r*'s sections sit at positions 5(*r*−1)+1 to 5*r*, code `r{round}s{section}` |
| lessons, videos, items, sources | as in version 1 |
| Round labels and goals, section difficulties, guide, resources, freshness watch | the import record (`academy_blueprints`, approved by the Owner) |
